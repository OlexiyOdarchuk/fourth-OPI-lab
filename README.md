# АС «Виклик таксі»

Консольний застосунок із модулями автоматизованої системи «Виклик таксі»:
оцінювання поїздок, звіти, розрахунок вартості, підбір водія та повний цикл
замовлення, що об'єднує ці модулі.

Лабораторна робота № 4 з дисципліни «Основи програмної інженерії», варіант 11.

## Можливості

| Пункт | Функція | Модуль | Автор |
|---|---|---|---|
| 1 | Оцінювання поїздки (UC11) | `src/trip_rate.rs` | Олексій Одарчук |
| 2 | Формування звітів (UC17) | `src/report_writer.rs` | Богдан Лиходій |
| 3 | Розрахунок вартості та оплата (UC6) | `cpp/fare_calculation.cpp` | Марія Цибко |
| 4 | Підбір водія (UC5) | `src/driver_matching.rs` | Даниїл Бойко |
| 5 | Повний цикл замовлення | `src/order_flow.rs` | Олексій Одарчук |

Міст між Rust і C++ із вводом даних і друком чека (`src/fare_calculation.rs`),
головне меню та спільний ввід — Олексій Одарчук.

- **Оцінювання поїздки** перераховує рейтинг водія після нової оцінки і визначає
  його рівень (Platinum, Gold, Standard, Risk) та пріоритет у розподілі замовлень.
  Водій із менш ніж 10 оцінками має рівень «Новий водій».
- **Формування звітів** будує звіт за період: кількість замовлень, виручка,
  кількість водіїв і їхня завантаженість.
- **Розрахунок вартості** рахує вартість за тарифом (подача, кілометри, хвилини)
  з урахуванням коефіцієнта попиту, промокоду й мінімальної вартості, виділяє
  ПДВ, комісію сервісу й виплату водію та друкує чек.
- **Підбір водія** шукає найближчого вільного водія потрібного класу в радіусі
  10 км і оцінює час подачі.
- **Повний цикл замовлення** проводить одне замовлення через усі модулі:
  підбирає водія, рахує вартість поїздки до пункту призначення й пропонує
  оцінити водія. Оплачені замовлення можна одразу використати у звіті.

Промокоди: `KNU2026` (знижка 20 %), `START` і `NEWUSER` (знижка 40 грн).

## Збірка та запуск

Потрібні Rust 1.88+ (edition 2024) і компілятор C++17 (`g++` або `clang++`).

```sh
cargo run              # зібрати й запустити
cargo build --release  # оптимізована збірка: target/release/taxi_app
```

Застосунок читає відповіді зі стандартного вводу, тому тестові дані можна
подати з файлу:

```sh
cargo run -q < test_data/scenarios.txt
```

`test_data/scenarios.txt` містить 27 сценаріїв поспіль:

- **оцінювання поїздки** — рівні Gold і Risk, новий водій, повторені
  компліменти, рейтинг поза діапазоном, кількість поїздок текстом;
- **звіти** — усі показники, період без даних, дата завершення раніше
  початку, час замовлень більший за час на лінії;
- **розрахунок вартості** — коефіцієнт попиту з промокодами `KNU2026`
  і `START`, доплата до мінімальної вартості, відмова від промокоду «ні»,
  коефіцієнт поза межами, нульова дистанція, дистанція понад 1000 км;
- **підбір водія** — найближчий водій, водій на відстані 6 км, немає
  вільних водіїв, межа радіуса 10 км, невідомий клас авто;
- **повний цикл** — два оплачені замовлення, скасоване замовлення, пункт
  призначення в місці посадки і звіт за оплаченими замовленнями.

## Технології

Застосунок написано на Rust, модуль розрахунку вартості — на C++17. Їх
поєднує бібліотека [`cxx`](https://cxx.rs): спільні типи описано в мості
`#[cxx::bridge]` у `src/fare_calculation.rs`, а `build.rs` компілює C++ код
у статичну бібліотеку, яка лінкується в один виконуваний файл. Суми грошей
зберігаються в копійках цілими числами, щоб уникнути похибок округлення.

## Структура

```
.
├── build.rs                 # збірка C++ коду та моста cxx
├── cpp/
│   └── fare_calculation.cpp # розрахунок вартості
├── src/
│   ├── main.rs              # головне меню
│   ├── input.rs             # читання вводу
│   ├── trip_rate.rs         # оцінювання поїздки
│   ├── report_writer.rs     # формування звітів
│   ├── fare_calculation.rs  # міст до C++, ввід і чек
│   ├── driver_matching.rs   # підбір водія
│   └── order_flow.rs        # повний цикл замовлення
└── test_data/
    └── scenarios.txt        # приклад вхідних даних
```
